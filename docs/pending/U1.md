# U1: `azhaq hunt`

Proposed text, by document. Nothing here is applied.

## README.md

Command table, "Read and compare results": `hunt`: "where to look first: the mapped routes, hosts and files ranked, each with its evidence and the next command".

New section after the one on `query`, "Where to look first":

> A map of thousands of routes does not say where to start. `azhaq hunt -db app.db` ranks it: one row per route template (`/rest/basket/6` and `/rest/basket/7` are one row), each with its score, the reasons for it and the command to run next.
>
>     azhaq hunt -db app.db
>     azhaq roles -json -role anon -role 'user=Authorization: Bearer …' -- -url https://app/ > roles.jsonl
>     azhaq hunt -db app.db -roles roles.jsonl -limit 10
>
> What raises a row, strongest first: a role reading or writing another role's object (from `-roles`, with the evidence and its confidence quoted); a name another party may take over; a credential or a source map in a script (the file is named); a backup, key or database file, a directory listing; admin, debug, config and internal paths; API descriptions and GraphQL endpoints; an object identifier in the path or an `id` parameter; parameters that take a URL, a file, a command, a redirect or a query; a write method no description asks credentials for; a file upload form; a GET that looks state-changing; a server error. First seen within `-since` (default 7 days) adds a little, and a row with only that never ranks. Static assets, scripts, images, fonts and catch-all pages never rank. Ties go to the target before fan-out, then to the row with more distinct signals, then by key.
>
> The `next` command is a real invocation: `azhaq roles show -dir DIR URL` for a cross-role row (DIR is the `-dir` of the roles run), `azhaq roles …` for an identifier, `azhaq params -u URL -w WORDLIST` for a page that takes input, `azhaq show -db FILE URL` for the rest.

## docs/OUTPUT.md

New section "hunt":

- Text: one row per line, `rank  score  key  reason; reason  → next: COMMAND`; a reason is `signal: detail`.
- `-json`: one object per row, `rank`, `score`, `key`, `type` (`URL` or `Hostname`), `reasons` (array of `{signal, detail}`), `next`. The summary on stderr counts `rows`.
- Signals: `cross-role`, `takeover`, `secret`, `sourcemap`, `exposed-file`, `listing`, `api-description`, `graphql`, `object-id`, `unauth-write`, `upload`, `state-change`, `password-in-url`, `gated`, `server-error`, `input`, `new`, `param-command|url|file|debug|redirect|query|callback`, `path-admin|debug|config|env|doc|function|data`.
- A key with `{n}`, `{uuid}`, `{hex}` or `={v}` is a template folding several URLs; a key seen once is the URL itself.

## docs/RECIPES.md

Recipe "Start a test from a map": run, `azhaq hunt -db app.db`, then `azhaq roles` with two accounts and `azhaq hunt -db app.db -roles roles.jsonl`.
