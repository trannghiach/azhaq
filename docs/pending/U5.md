# U5: the request ledger and the kill switch

Proposed text, by document. Nothing here is applied.

## README.md

New section after the one on scope and request budgets, "Proving what was sent":

> Every run with a workspace writes `DB.ledger.jsonl` next to it: one JSON line for each request or connection sent to a target (HTTP, Chrome's requests, port connects, TLS handshakes) with its time, URL or `ip:port`, host, the scope rule that allowed it (`-allow`, `-scope`; empty when the run has no rules) and the collector. Each line carries the hash of the one before, so an edited, removed or reordered line is caught. DNS queries and the third-party sources of `subs` and `urls` are not targets and are not listed. `azhaq resume` appends to the same file.
>
>     azhaq ledger -verify app.db.ledger.jsonl    # exit 0 intact; exit 3 naming the first bad line
>     azhaq ledger -summary app.db.ledger.jsonl   # counts by kind, host, method, scope rule; first and last time
>     azhaq ledger -csv app.db.ledger.jsonl       # for a client report or a blue team's deconfliction
>
> `-ledger FILE` writes it elsewhere, `-ledger off` not at all. A drop-in command without `-db` uses a temporary workspace and writes a ledger only with `-ledger FILE`.
>
> `-kill-file PATH` (default `DB.stop`) is the kill switch: create the file and, within half a second, nothing more is sent. The run exits 4 with `stopped` naming the kill switch; remove the file and `azhaq resume -db DB` continues. `azhaq roles` uses one ledger, `roles.ledger.jsonl`, and one stop file, `roles.stop`, in its `-dir`.

Command table: add `ledger` to "Read and compare results": "check, count or export the record of what a run sent".

Flags table of `run` (and `ports`, `dirs`, `params`, `probe`, `crawl`, `shots`): `-ledger`, `-kill-file`.

## docs/OUTPUT.md

- Exit codes: exit 4 is also "stopped by the kill file".
- Summary `notes`: `ledger: N requests and connections recorded in FILE (azhaq ledger -verify FILE)`.
- Ledger line fields: `seq`, `time` (UTC), `kind` (`http`, `tcp`, `chrome`), `method`, `target`, `host`, `rule`, `collector`, `prev`, `hash` (hex sha256 of `prev` and the line's JSON without `hash`).

## docs/RECIPES.md

"Deconfliction and audit": give the client's blue team `azhaq ledger -csv`; show `-verify` passing on the file as delivered; stop a run from another terminal with `touch app.db.stop`.

## docs/TROUBLESHOOTING.md

"The run stopped at once with exit 4 and a kill file": the file `DB.stop` (or the one `-kill-file` names) exists, also from an earlier stop; remove it and `azhaq resume`.

## docs/ARCHITECTURE.md

`internal/ledger`: the chain, the hooks (`fetch.Client` and `fetch.Do` wrap every target-facing transport; portscan and tlscol record connects; the browser records the requests it lets Chrome send), and `fetch.SetKill`, which makes `Spend`, `Take` and `Spent` refuse with `neterr.ErrKilled` (also an `ErrBudget`, so every collector that leaves work for resume on a spent budget does so here).
