# W2: `azhaq fuzz` and memory (proposed text)

## README / commands: One job each

**`azhaq fuzz`** (like ffuf). Words from a wordlist put into a request, anywhere in
it: the path, a query value, a header (`Host: FUZZ.example.com` for virtual hosts),
the method, a JSON or form body. It takes ffuf's flags and counts the way ffuf 2.3
does (words are spaces plus one, lines newlines plus one, the same match and filter
rules, the same calibration), so a command line moved from ffuf gives the same results.

    azhaq fuzz -u https://app.example.com/FUZZ -w common.txt -e .php,.bak -recursion -recursion-depth 2
    azhaq fuzz -u https://app.example.com/login -X POST -H 'Content-Type: application/json' \
      -d '{"user":"USER","password":"PASS"}' -w users.txt:USER -w pass.txt:PASS -mode pitchfork -mr 'welcome'
    azhaq fuzz -u https://10.0.0.5/ -H 'Host: FUZZ.example.com' -w subdomains.txt -fs 4242 -json -db vhosts.db

Flags: `-u`, `-w FILE[:KEYWORD]` (repeatable), `-mode clusterbomb|pitchfork`, `-X`,
`-d`, `-H`, `-b`, matchers `-mc -ms -mw -ml -mr` (a result is shown when it matches any
of them; `-mmode and` wants all), filters `-fc -fs -fw -fl -fr` (any drops it; `-fmode
and`), `-ac` (on by default, `-ac=false` is ffuf's default), `-ack`, `-recursion`,
`-recursion-depth`, `-e`, `-ic`, `-t` (40), `-rate`, `-timeout` (seconds per request, as
in ffuf), `-maxtime`, `-r`, `-v`, `-s`/`-silent`, `-json`, `-o`, `-db`, and the house
flags `-scope`, `-program`, `-allow`, `-deny`, `-max-requests`.

Differences from ffuf:

- Auto-calibration is on. It needs the keyword `FUZZ` (or the one `-ack` names) in the
  request; without it a note says nothing was calibrated.
- The default matcher is `-mc 200-299,301,302,307,401,403,405,500` unless `-ms`, `-mw`,
  `-ml` or `-mr` is given alone, as in ffuf.
- With several wordlists, `-mode pitchfork` runs as long as the longest list and the
  shorter ones start over (ffuf 2.3: 4 users and 3 passwords make 4 requests, not 3).
- Every request goes through the run's budget and pace (`-max-requests`, `-rate`). The
  host in `-u` is the scope unless `-allow`, `-deny` or `-scope` say otherwise; when the
  keyword starts the host (`FUZZ.example.com`) the scope is its domain. A request to a
  host outside the scope is not sent and the summary counts it.
- Five unanswered requests in a row stop the run: the target is down (exit 3, the
  origin is listed under "did not answer").
- `-o FILE` writes what stdout shows (not ffuf's JSON report); `-db FILE` keeps the
  matches in a workspace as ffuf results are, for `query`, `show` and `export`.
- `-json` prints ffuf's fields (`input` values are base64 as ffuf prints them); the
  summary is one JSON line on stderr. Exit codes 0 to 4 as in every command.

## docs/OUTPUT.md

`fuzz -json` row: `{"input":{"FUZZ":"YWRtaW4="},"position":12,"status":200,"length":483,
"words":51,"lines":7,"content-type":"text/plain","redirectlocation":"","url":"…",
"duration":7596361,"host":"127.0.0.1:3001"}`. `duration` is nanoseconds to the first byte.

## README / memory

Every command used to allocate 15 MB at start for CDN ranges (cdncheck parsed a 2.4 MB
file in init). The ranges are now read the first time an address is checked
(`internal/cdnranges`), and the patterns of `internal/webextract` compile when first
used. `azhaq version` runs in 16 MB, not 31.
