## docs/OUTPUT.md, the summary and the subs command

`subs` counts the sources it asked, in the summary's `counts`:

| count | meaning |
|---|---|
| `sources asked` | passive sources that ran for the domains given (skipped ones, such as a keyed source with no key, are not counted) |
| `sources answered` | those that returned without an error |
| `sources failed` | failures of sources in the default set, or named with `-sources` |
| `off-by-default failed` | failures of sources that ran only because of `-all-sources` |

`asked = answered + failed + off-by-default failed`.

The summary has a top-level `degraded: true` when `sources failed` is above 0: a source the run relies on did not answer, so the names may be incomplete. It does not change the exit code: a failure the other sources made up for is listed as partial and the exit stays 0 (3 with `-fail-on-errors`). Failures of off-by-default sources never set `degraded` on their own.

The per-source status in the db (`azhaq query -db FILE`, the `sources` payload of `azhaq-subdomains`) has `"default": false` on a source that ran only because of `-all-sources`.
