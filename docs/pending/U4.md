# U4: azhaq report (proposed text)

## README, "Access control with evidence", and docs/OUTPUT.md next to `roles show`

`azhaq report -dir DIR` writes up what `azhaq roles` found as one Markdown
report per finding, ready to paste into HackerOne or Bugcrowd, or into a red
team's client report. It reads the evidence the roles run kept in
`DIR/roles.db` and sends nothing.

    $ azhaq report -dir azhaq-roles-20261028-101500
    azhaq report: 3 reports in azhaq-roles-20261028-101500/reports
      …/01-proved-get-books-v1-book-title.md  [proved] Broken object level authorization: bob reads alice's book via GET /books/v1/{book_title}
      …/02-proved-get-books-v1-book-title.md  [proved] Broken object level authorization: alice reads bob's book via GET /books/v1/{book_title}
      …/03-unrated-get-users-v1-debug.md  [unrated] Excessive data exposure: anyone reads password via GET /users/v1/_debug

Without `-url`, it writes a report for each listed row whose verdict is
`reads another role's object`, `writes another role's object`, `anyone writes
another role's object` or `anyone reads sensitive fields`, ordered by
confidence (`proved`, `likely`, `guess`, then rows that carry none). With
`-url URL` (and `-method M` for a write row) it writes that one report to
standard output.

| Flag | |
|---|---|
| `-dir DIR` | the `-dir` of the roles run (it holds `roles.db`) |
| `-url URL`, `-method M` | one row only; a row that is not one of the four verdicts is refused |
| `-format md\|json` | Markdown (default), or the same content as structured fields |
| `-o PATH` | a file (the reports one after another, a JSON array for `json`), or a directory (`out/`, or an existing one) with a file per report; default: `DIR/reports` |
| `-redact` | also mask hosts (`<host>`) and identifiers (`<id-1>`) |

Each report has a title naming the bug class (broken object level
authorization for a read, "(write)" for a write, excessive data exposure for
sensitive fields anyone reads), a two-sentence summary, a severity that is
labelled a guess and says why (sensitive fields and a write raise it),
numbered steps with the curl commands from the evidence (the session as
`$ALICE_TOKEN`, `$BOB_TOKEN`), the evidence (status, length and the relevant
JSON fields of the owner's answer, the reader's, and the control: what a
made-up identifier returned), the row's `owner_by` quoted as the reason the
object is the owner's, impact and remediation by class, and notes (confidence,
both ways, "found by azhaq roles, run DATE").

A report never says what the evidence does not hold. A row with no control, a
body that was not kept, no `owner_by`, or an evidence file from an older
azhaq (no run date) says so in the report, under "Missing from the evidence
store". A write's before-and-after reads of the owner's object are not kept;
the report says so.

`-redact` is for a report that leaves the engagement: the host becomes
`<host>`, the identifier in the route and the values of identifier fields in
the kept bodies (`id`, `*Id`, `username`, `owner`, `email`, …) become
`<id-N>`, and any token is removed. Role names are the tester's own labels and
stay. Read a redacted report once before sharing it: an identifier no kept body
names in an identifier field is not masked.

## docs/OUTPUT.md: report JSON

`-format json` holds, per report: `title`, `class` (`bola_read`, `bola_write`,
`excessive_data_exposure`), `method`, `url`, `route`, `verdict`, `confidence`
(`unrated` when roles gave none), `summary`, `severity_guess` (`level`,
`reason`), `variables`, `steps` (`n`, `text`, `curl`, `expect`), `evidence` (per
answer: `role`, `kind` owner/reader/other/control, `request`, `status`,
`length`, `content_type`, `body_kept`, `fields`), `owner_reason`, `impact`,
`remediation`, `notes` (`confidence`, `both_ways`, `found_by`, `run`) and
`missing`.

## docs/ARCHITECTURE.md (store)

`roles.db` also records when the run saved it (`saved_at`), which the report
quotes as the run date.
