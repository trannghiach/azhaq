# U2: route-level change detection in watch (proposed text)

## README / watch, and docs/OUTPUT.md next to the `watch` change set

`watch` also says what changed in an app's API surface, tied to the script
that calls each route. A frontend deploy that adds a route adds attack
surface, and the first report is the one that pays. A section "API routes"
lists one line per change:

    ~ 4 API routes
        + POST /api/v2/export {format, userId}  (main.js)
        ~ /api/orders/{id}: +DELETE  (main.js)
        ~ PUT /api/profile: +role  (main.js)
        - /api/legacy/report  (main.js)

- `+` a new route: its methods and the names it sends (query and body).
- `~ /route: +DELETE` a method added to (or `-GET` removed from) a known route.
- `~ PUT /route: +role` a name the route's call now sends (or `-name`).
- `-` a route the previous run's scripts or API description named, that no
  source names in this run. A route only found by guessing or in an archive is
  never reported gone, and one a crawl or a guess finds is not reported new:
  routes are compared where a script or an API description names them.

Placeholder names (`{id}` or `{orderId}`), identifiers, ordering and case do
not count as changes, so the same app mapped twice reports no route change. A
route that answers differently (status, title, item count) stays under "pages
that answer differently". The first run of a workspace lists no routes: there
is nothing to compare it to.

The same text goes to Slack, Discord and Telegram. The JSON for `-notify-cmd`,
`-json` and generic hooks has a `routes` field:

    "routes": [
      {"kind": "new", "host": "app.example.com", "route": "/api/v2/export",
       "methods_added": ["POST"], "fields_added": ["format", "userId"],
       "script": "https://app.example.com/main.js"},
      {"kind": "methods", "route": "/api/orders/{id}", "methods_added": ["DELETE"], …},
      {"kind": "fields", "route": "/api/profile", "method": "PUT", "fields_added": ["role"], …},
      {"kind": "gone", "route": "/api/legacy/report", "methods_removed": ["GET"], …}
    ]

`kind` is `new`, `methods`, `fields` or `gone`; `script` is the first script
that names the route. A route reported as new or gone is not repeated under
"URLs".
